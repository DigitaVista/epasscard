Card API (PHP and REST)

Issue, update, void and read a wallet card for a record of an active integration from your own code, or over the WordPress REST API. Available since 1.2.0.

Each call runs the integration's own sync, so the card gets the same design and field values as the automatic flow, and a record never gets a second card. Every card counts toward the EpassCard plan like any other.

Which record?

A card belongs to one record of an integration: the integration slug plus the record id that integration uses.

The integration must be turned on and its plugin active, and the site must be connected to EpassCard. Record ids are digits, or a lowercase prefix, an underscore and digits (sub_12).

PHP

PHP
// Create the card, or update it when it exists (a voided card is made live again).
				// 'email' => true sends the card link once (Settings → Emails), instead of the automatic email.
				$card = epc_issue_pass( 'paid-memberships-pro', $membership_row_id, array( 'email' => true ) );
				
				// Update the existing card with the record's current values. Error when there is no card.
				$card = epc_update_pass( 'paid-memberships-pro', $membership_row_id );
				
				// Void: the card expires in Apple Wallet and Google Wallet and shows as revoked.
				$card = epc_void_pass( 'paid-memberships-pro', $membership_row_id );
				
				// Read.
				$card = epc_get_pass( 'paid-memberships-pro', $membership_row_id );
				
				if ( is_wp_error( $card ) ) {
				    error_log( $card->get_error_code() . ': ' . $card->get_error_message() );
				}

Each function returns an array or a WP_Error:

KeyTypeNotes
modulestringIntegration slug
source_idstringRecord id
entity_idintPlan, level, event or product id
user_idintWordPress user the card belongs to (0 = none)
pass_uidstringCard id at EpassCard
pass_linkstringLink that adds the card to Apple Wallet or Google Wallet
statusstringactive or revoked
is_testboolA test card from the Try it step
created_at, updated_atstringDatabase time
createdboolepc_issue_pass() only: this call created the card
emailedboolepc_issue_pass() only: the email went out (email_error holds the reason when not)

The functions do not check the current user's capabilities; check them in your code.

REST

Namespace epasscard/v1. Requests need a user who can manage cards (administrators, and staff with the EpassCard staff capability): use an application password or the REST nonce.

MethodRouteDoes
POST/passes (body: module, source_id, optional email)Issue. 201 when the card was created, 200 when it was updated
GET/passes/{module}/{source_id}Read
PUT, PATCH/passes/{module}/{source_id}Update
DELETE/passes/{module}/{source_id}Void
Shell
curl -u "admin:APPLICATION PASSWORD" -X POST \
				  https://example.com/wp-json/epasscard/v1/passes \
				  -d module=woocommerce-loyalty -d source_id=42 -d email=true
